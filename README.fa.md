# نور — Noor Micro MVC PHP Framework

**نسخه 1.0.0-stable** — یک میکروفریمورک مستقل با PHP 8.2+، بدون Composer و بدون وابستگی اجباری.

Noor برای این ساخته شده که هم بتوانی روی آن وب‌اپلیکیشن بسازی و هم خود هسته‌اش را بفهمی. اگر بخواهی بعداً کسی از تو بپرسد «چرا این ساختار را انتخاب کردی؟» باید بتوانی جواب فنی و روشن بدهی؛ به همین خاطر در نور، کدها، ساختار پوشه‌ها و مستندات تا جای ممکن شفاف نگه داشته شده‌اند.

## در این نسخه چه چیزهایی داری؟

- صفحه معرفی حرفه‌ای با هویت بصری جدید و لوگوی شیر و خورشید
- مستندات داخلی قابل مرور در مسیر `/docs`
- Router با پشتیبانی از GET، POST، PUT، PATCH، DELETE و پارامترهای URL
- کلاس‌های Request و Response برای مدیریت تمیز ورودی و خروجی HTTP
- ساختار MVC ساده و قابل فهم
- Middleware، CSRF، Session، Validation و ابزارهای پایه امنیتی
- لایه سبک دیتابیس بر پایه PDO و Transaction
- تست‌های خودکار بدون نیاز به PHPUnit و Composer

## اجرای سریع در XAMPP

1. فایل ZIP را در `C:\xampp\htdocs\noor` استخراج کن.
2. Apache را در XAMPP روشن کن.
3. آدرس `http://localhost/noor/public/` را باز کن.
4. برای دیدن مستندات، `http://localhost/noor/public/docs` را باز کن.
5. برای اجرای تست‌ها از این دستور استفاده کن:

```bash
C:\xampp\php\php.exe tests\run.php
```

اگر از سرور داخلی PHP استفاده می‌کنی:

```bash
php -S 127.0.0.1:8000 -t public public/router.php
```

## چرا Noor این‌طوری طراحی شده است؟

### چرا Front Controller داریم؟
چون می‌خواهیم همه درخواست‌ها از یک نقطه مشترک وارد برنامه شوند. این کار باعث می‌شود مدیریت خطا، Session، Autoload و امنیت پایه در یک محل کنترل شوند.

### چرا Request و Response کلاس هستند؟
چون ورودی و خروجی HTTP باید ساختارمند باشند. وقتی Controller به‌جای `echo` کردن یک `Response` برمی‌گرداند، تست نوشتن و توسعه بعدی بسیار ساده‌تر می‌شود.

### چرا ORM و سیستم پیچیده تزریق وابستگی داخل هسته نگذاشتیم؟
چون هدف Noor داشتن یک هسته کوچک و شفاف بوده است. هر قابلیت جدید فقط وقتی وارد هسته می‌شود که نیاز واقعی آن ثابت شده باشد، تست داشته باشد و API آن روشن باشد.

### چرا View ساده PHP نگه داشته شده؟
چون می‌خواهیم توسعه‌دهنده بدون یادگیری یک Template Engine جداگانه بتواند سریع Viewها را بخواند و تغییر دهد.

## نکته مهم

این نسخه **stable** است؛ یعنی هسته و قابلیت‌های فعلی آن تثبیت شده‌اند و تست‌های خودکار پروژه از آن عبور کرده‌اند. با این حال، مثل هر پروژه نرم‌افزاری دیگر، قبل از انتشار عمومی نرم‌افزار نهایی باید دیتابیس، سرور، Session، امنیت و سناریوهای واقعی خودت را جداگانه بررسی کنی.

## فایل‌های مهم برای مطالعه

- `public/index.php` : نقطه ورود تمام درخواست‌ها
- `bootstrap.php` : Autoload و بارگذاری کلاس‌ها
- `config/routes.php` : تعریف Routeها
- `src/Noor/Core/Router.php` : منطق مسیریابی
- `src/Noor/Http/Request.php` : خواندن داده‌های درخواست
- `src/Noor/Http/Response.php` : ساخت پاسخ HTTP
- `app/Views/home.php` : صفحه اصلی سایت
- `app/Views/docs/pages/` : صفحات مستندات داخلی

برای فهم عمیق‌تر، از صفحه `docs/architecture` و `docs/api` شروع کن.
